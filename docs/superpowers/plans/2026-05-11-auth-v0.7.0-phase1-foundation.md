# Auth v0.7.0 Phase 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lay the multi-tenant + identity foundation for v0.7.x auth — schema with `org_id` everywhere, JWT extended with `user_id`/`org`/`jti` claims, query scoping across all services, middleware backward-compat for v0.6 clients, structural hooks for v0.7.5 encryption + v0.8 compliance.

**Architecture:** Phase 1 ships **no user-visible change**. Existing v0.6 clients keep working under `AUTH_ENABLED=false` via synthetic legacy claims. New tables (`orgs`, `users`, `refresh_tokens`, `device_auth_requests`, `audit_log`) and interfaces (`IdPProvider`, `EncryptionProvider`) ship empty/unused — Phase 2 (`v0.7.1`) hangs OAuth on them. All existing tables gain an `org_id` column defaulted to `'default'`; every query in every service is rewritten to scope by `org_id`.

**Tech Stack:** TypeScript, `jose` (HS256 JWT), `better-sqlite3` / `bun:sqlite`, `aedes` (MQTT), `vitest` for tests. Existing pattern: services injected via `CoordinatorServices` in `src/server-setup.ts`, services receive DB via `getDb()`.

**Spec:** `docs/superpowers/specs/2026-05-11-auth-saas-ready-design.md` (831 lines, amended by PR #18). Phase 1 covers spec sections A, B, B.5, C, D, J + the operational/security items applicable to v0.7.0 (algorithm pinning, secret rotation, WWW-Authenticate, DB mode 0600).

**Out of scope (deferred to later phases):** OAuth providers (Phase 2), Device Flow endpoints (Phase 2), CLI login + PKCE (Phase 3), Google/OIDC (Phase 4), SQLCipher encryption (v0.7.5).

## Conventions used throughout

**Test directory naming**: Each test file creates its own `data-test-<name>/` directory and removes it in `afterAll`. Follow `tests/unit/auth.test.ts` lines 1-22.

**Org propagation**: `authenticateRequest` returns `claims.org`. Every handler in `handle-rest.ts` extracts `claims.org` and passes it as the **first argument** to every service method. Services pass it directly into SQL bindings (no globals).

**Backward-compat default**: When `AUTH_ENABLED=false` and no Authorization header is present, claims default to `{user_id: 'legacy', org: 'default', role: 'admin'}`. This is the synthetic claim block returned by middleware.

**Idempotent migrations**: Every `ALTER TABLE` is wrapped in `try { ... } catch { /* already exists */ }`, matching the existing pattern in `database.ts:225-242`.

**TDD**: For each task, write the failing test first, verify it fails for the right reason, write minimal implementation, verify it passes, commit. The skill's "minimal" means: enough to pass the test, no scaffolding for tasks ahead.

**Commit cadence**: One logical change per commit. Use the existing `feat(auth):`, `chore(db):`, `test(auth):` convention.

**Pre-commit hooks**: The repo has pre-commit checks (typecheck + lint). If they fail after a code change, fix the underlying issue and create a NEW commit — never `--no-verify`.

## Task 11: Four-scenario `authenticateRequest` backward-compat

The new `authenticateRequest` implements the table from spec §J/§Migration:

| Scenario | Behavior |
|---|---|
| (a) No Auth header + `AUTH_ENABLED=false` | Inject synthetic `{user_id:'legacy', org:'default', role:'admin'}` |
| (b) No Auth header + `AUTH_ENABLED=true` | 401 + WWW-Authenticate |
| (c) Old v0.6 JWT (no user_id/org claims) + `AUTH_ENABLED=false` | Accept; verify; inject missing claims as legacy |
| (d) New v0.7 JWT (has user_id/org) | Standard verify (works in both AUTH_ENABLED values) |

  let payload: Awaited<ReturnType<typeof jwtVerify>>["payload"];

    const rows = db.prepare(
      `SELECT file_path, COUNT(DISTINCT agent_id) as agent_count, GROUP_CONCAT(DISTINCT agent_id) as agents
       FROM file_activity
       WHERE org_id = ?
         AND created_at > datetime('now', '-' || ? || ' minutes')
       GROUP BY file_path
       HAVING COUNT(DISTINCT agent_id) > 1
       ORDER BY agent_count DESC`
    ).all(orgId, sinceMinutes) as { file_path: string; agent_count: number; agents: string }[];
    return rows.map((r) => ({
      file_path: r.file_path,
      agent_count: r.agent_count,
      agents: r.agents.split(","),
    }));
  }

  checkFileConflict(orgId: string, filePath: string, agentId: string, withinMinutes: number = 30): { conflict: boolean; agents: string[] } {
    const db = getDb();
    const rows = db.prepare(
      `SELECT DISTINCT agent_id FROM file_activity
       WHERE org_id = ? AND file_path = ? AND agent_id != ?
         AND created_at > datetime('now', '-' || ? || ' minutes')`
    ).all(orgId, filePath, agentId, withinMinutes) as { agent_id: string }[];

import { getDb } from "./database.js";
import type { CoordinatorEvent, EventType } from "./types.js";

type EventListener = (event: CoordinatorEvent) => void;

interface ListenerEntry {
  orgId: string;
  listener: EventListener;
}

interface EmitOptions {
  org_id: string;
}

const DEFAULT_MAX_SSE_CLIENTS = 100;

export const MAX_SSE_CLIENTS = (() => {
  const raw = process.env.COORDINATOR_MAX_SSE_CLIENTS;
  if (!raw) return DEFAULT_MAX_SSE_CLIENTS;
  const n = parseInt(raw, 10);
  return Number.isFinite(n) && n > 0 ? n : DEFAULT_MAX_SSE_CLIENTS;
})();

const NOOP = () => {};

export class SseEmitter {
  private entries: ListenerEntry[] = [];
  private rejectedCount = 0;

  emit(type: EventType, payload: Record<string, unknown>, options: EmitOptions): void {
    const db = getDb();
    const payloadWithOrg = { ...payload, org_id: options.org_id };
    const payloadStr = JSON.stringify(payloadWithOrg);
    const result = db
      .prepare("INSERT INTO events (org_id, type, payload) VALUES (?, ?, ?)")
      .run(options.org_id, type, payloadStr);

    const event: CoordinatorEvent = {
      id: result.lastInsertRowid as number,
      type,
      payload: payloadStr,
      created_at: new Date().toISOString(),
    };

    // Snapshot + filter by org_id, then fan-out via setImmediate.
    const snapshot = this.entries.filter((e) => e.orgId === options.org_id);
    for (const entry of snapshot) {
      setImmediate(() => {
        try { entry.listener(event); } catch { /* drop */ }
      });
    }
  }

  getEventsSince(orgId: string, lastId: number): CoordinatorEvent[] {
    const db = getDb();
    return db
      .prepare("SELECT * FROM events WHERE org_id = ? AND id > ? ORDER BY id")
      .all(orgId, lastId) as CoordinatorEvent[];
  }

  addListener(orgId: string, listener: EventListener): () => void {
    if (this.entries.length >= MAX_SSE_CLIENTS) {
      this.rejectedCount++;
      return NOOP;
    }
    const entry: ListenerEntry = { orgId, listener };
    this.entries.push(entry);
    return () => {
      this.entries = this.entries.filter((e) => e !== entry);
    };
  }

  removeAllListeners(): void { this.entries = []; }
  listenerCount(): number { return this.entries.length; }
  getRejectedCount(): number { return this.rejectedCount; }
}
