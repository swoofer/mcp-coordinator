## Conventions used throughout

**Test directory naming**: Each test file creates its own `data-test-<name>/` directory and removes it in `afterAll`. Follow `tests/unit/auth.test.ts` lines 1-22.

**Module-state hygiene** (important under vitest's `fileParallelism: false`): the `src/auth.ts` module holds `signingKey` and `prevKey` at module scope. Any test file that mutates them mid-test (e.g., `auth-jwt-rotation.test.ts` which sets `prevSecret`) MUST reset them in `afterAll` to avoid contaminating subsequent test files in the same vitest worker. Pattern:

```typescript
afterAll(() => {
  initAuth(SECRET);  // Resets signingKey AND clears prevKey to null
  closeDb();
  fs.rmSync(DIR, { recursive: true, force: true });
});
```

Without this, a later-alphabetical test file (e.g., `composite-pk-migration.test.ts`) sees the stale `prevKey` and may accept tokens it shouldn't.

**Org propagation**: `authenticateRequest` returns `claims.org`. Every handler in `handle-rest.ts` extracts `claims.org` and passes it as the **first argument** to every service method. Services pass it directly into SQL bindings (no globals).

**Backward-compat default**: When `AUTH_ENABLED=false` and no Authorization header is present, claims default to `{user_id: 'legacy', org: 'default', role: 'admin'}`. This is the synthetic claim block returned by middleware.

**Idempotent migrations**: Every `ALTER TABLE` is wrapped in `try { ... } catch { /* already exists */ }`, matching the existing pattern in `database.ts:225-242`.

**TDD**: For each task, write the failing test first, verify it fails for the right reason, write minimal implementation, verify it passes, commit. The skill's "minimal" means: enough to pass the test, no scaffolding for tasks ahead.

**Commit cadence**: One logical change per commit. Use the existing `feat(auth):`, `chore(db):`, `test(auth):` convention.

**Pre-commit hooks**: The repo has pre-commit checks (typecheck + lint). If they fail after a code change, fix the underlying issue and create a NEW commit — never `--no-verify`.

## Task 5.5: Composite primary keys for cross-org collision safety

**Hard prerequisite for Tasks 19a, 19b, 19c, 19e and for `revoked_agents` correctness.** Without this task, the `ON CONFLICT(...)` clauses in those service refactors target single-column PKs (`agent_id`, `module_id`, `(file_a, file_b)`), so a second org's write silently overwrites the first org's row. Phase 1 is single-org (`'default'`) so this is latent, but landing the unsafe patterns now creates a future migration cliff AND leaves `revoked_agents` (a security gate consulted on every registration) cross-org-vulnerable.

**SQLite caveat**: there is no `ALTER TABLE ... ADD PRIMARY KEY` / `ALTER TABLE ... DROP PRIMARY KEY`. Changing a PK requires create-new-table + copy + drop-old + rename. This is the standard SQLite migration pattern. It briefly locks writes (acceptable per the spec's existing ALTER note).

**Tables that need composite PK `(org_id, <existing_pk>)`:**

| Table | Old PK | New PK | Reason |
|---|---|---|---|
| `agents` | `id` | `(org_id, id)` | Task 16 upsert by id |
| `agent_activity_status` | `agent_id` | `(org_id, agent_id)` | Task 19a upsert by agent_id |
| `dependency_map` | `module_id` | `(org_id, module_id)` | Task 19b upsert by module_id |
| `git_cochange` | `(file_a, file_b)` | `(org_id, file_a, file_b)` | Task 19c INSERT OR REPLACE |
| `git_cochange_meta` | `k` | `(org_id, k)` | Task 19c meta sentinel |
| `revoked_agents` | `agent_id` | `(org_id, agent_id)` | **SECURITY**: revocation gate on register |
| `working_files` | `(agent_id, file_path)` | `(org_id, agent_id, file_path)` | Task 18 claim semantics |

> **NOT migrated**: `introspections` (PK is `id` UUID — globally unique, no cross-org collision possible); `threads`, `thread_messages`, `action_summaries`, `file_activity`, `events`, `layer_firings` (all use UUIDs or autoincrement, no collision risk).

```typescript
// v0.7: SQLite lacks ALTER PRIMARY KEY. Pattern per table:
//   1. Create new table with composite PK.
//   2. Copy all rows from old to new.
//   3. Drop old.
//   4. Rename new to old.
//   5. Recreate indexes.
// Idempotent: skip if the table's PK already includes org_id.
function migrateToCompositePK(
  db: DatabaseAdapter,
  tableName: string,
  newCreateSql: string,
  columnList: string,
  indexCreateSqls: string[],
): void {
  // Check if migration already happened by inspecting PK columns
  const cols = db.prepare(`PRAGMA table_info(${tableName})`).all() as { name: string; pk: number }[];
  const pkCols = cols.filter((c) => c.pk > 0).map((c) => c.name);
  if (pkCols.includes("org_id")) return; // already migrated

  // SQLite: FK enforcement blocks DROP TABLE when other tables hold FK refs.
  // PRAGMA foreign_keys must be toggled OUTSIDE the transaction (it's a no-op
  // inside an open transaction). The finally block guarantees FKs are re-enabled
  // even on error to avoid permanent corruption.
  db.exec("PRAGMA foreign_keys = OFF");
  try {
    db.exec("BEGIN");
    try {
      db.exec(newCreateSql.replace(tableName, `${tableName}_new`));
      db.exec(`INSERT INTO ${tableName}_new (${columnList}) SELECT ${columnList} FROM ${tableName}`);
      db.exec(`DROP TABLE ${tableName}`);
      db.exec(`ALTER TABLE ${tableName}_new RENAME TO ${tableName}`);
      for (const idxSql of indexCreateSqls) db.exec(idxSql);
      db.exec("COMMIT");
    } catch (e) {
      db.exec("ROLLBACK");
      throw e;
    }
  } finally {
    db.exec("PRAGMA foreign_keys = ON");
  }
}
```

## Task 11: Four-scenario `authenticateRequest` backward-compat

The new `authenticateRequest` implements the table from spec §J/§Migration:

| Scenario | Behavior |
|---|---|
| (a) No Auth header + `AUTH_ENABLED=false` | Inject synthetic `{user_id:'legacy', org:'default', role:'admin'}` |
| (b) No Auth header + `AUTH_ENABLED=true` | 401 + WWW-Authenticate |

```typescript
export async function verifyTokenStrict(token: string): Promise<{ claims: AuthClaims; wasLegacy: boolean }> {
  let payload: Awaited<ReturnType<typeof jwtVerify>>["payload"];
  try {
    ({ payload } = await jwtVerify(token, signingKey, { algorithms: ["HS256"] }));
  } catch (err) {
    if (prevKey && err instanceof errors.JWSSignatureVerificationFailed) {
      ({ payload } = await jwtVerify(token, prevKey, { algorithms: ["HS256"] }));
    } else {
      throw err;
    }
  }
  if (!payload.sub) throw new Error("Missing sub claim in token");
  // Tolerate missing/unknown role on v0.6 tokens (some pre-v0.3 tokens lacked it
  // entirely). Default to 'member' (LEAST PRIVILEGE) — not 'admin'.
  // The synthetic legacy-claims block in authenticateRequest (no-Bearer path)
  // does grant 'admin', which is the explicit open-coordinator contract for
  // unauthenticated requests. But a token that was signed by our secret yet
  // omitted role is an internal minting bug, not an admin grant. Defaulting
  // to 'member' contains the blast radius of such bugs.
  const rawRole = payload.role;
  const role: AuthRole =
    rawRole === "agent" || rawRole === "admin" || rawRole === "member"
      ? rawRole
      : "member";
  // v0.7 detection requires BOTH user_id AND org to be present strings.
  // A partial token (one but not the other) is treated as legacy and rejected
  // when AUTH_ENABLED=true.
  const hasV07 = typeof payload.user_id === "string" && typeof payload.org === "string";
  return {
    claims: {
      sub: payload.sub, role,
      user_id: typeof payload.user_id === "string" ? payload.user_id : "legacy",
      org: typeof payload.org === "string" ? payload.org : "default",
      jti: typeof payload.jti === "string" ? payload.jti : randomUUID(),
    },
    wasLegacy: !hasV07,
  };
}
```

### Task 11 Step 7: Update `refreshToken` to gate v0.6 tokens

`refreshToken` (from Task 9) currently calls `verifyToken` directly, which silently injects `user_id='legacy'`/`org='default'` for missing claims.
```typescript
export async function refreshToken(
  token: string,
  options: { authEnabled: boolean },
  gracePeriod = "1h",
): Promise<string> {
  let result: Awaited<ReturnType<typeof verifyTokenStrict>>;
  try {
    result = await verifyTokenStrict(token);
  } catch (err) {
    if (err instanceof errors.JWTExpired) {
      // Expired tokens — retry with clockTolerance grace period, against both keys.
      const verifyWith = async (key: Uint8Array) =>
        jwtVerify(token, key, { clockTolerance: gracePeriod, algorithms: ["HS256"] });
      let payload: Awaited<ReturnType<typeof jwtVerify>>["payload"];
      try {
        ({ payload } = await verifyWith(signingKey));
      } catch (err2) {
        if (prevKey && err2 instanceof errors.JWSSignatureVerificationFailed) {
          ({ payload } = await verifyWith(prevKey));
        } else { throw err2; }
      }
      if (!payload.sub) throw new Error("Missing sub claim in token");
      const rawRole = payload.role;
      const role: AuthRole =
        rawRole === "agent" || rawRole === "admin" || rawRole === "member" ? rawRole : "member";
      const hasV07 = typeof payload.user_id === "string" && typeof payload.org === "string";
      result = {
        claims: {
          sub: payload.sub, role,
          user_id: typeof payload.user_id === "string" ? payload.user_id : "legacy",
          org: typeof payload.org === "string" ? payload.org : "default",
          jti: typeof payload.jti === "string" ? payload.jti : randomUUID(),
        },
        wasLegacy: !hasV07,
      };
    } else { throw err; }
  }

  // CRITICAL gate: v0.6 tokens cannot be refreshed under AUTH_ENABLED=true.
  // Same invariant as authenticateRequest — keeps /api/auth/refresh from being
  // a bypass for the wasLegacy reject.
  if (result.wasLegacy && options.authEnabled) {
    throw new Error("Cannot refresh a v0.6 token under AUTH_ENABLED=true. Re-authenticate to obtain a v0.7 token.");
  }

  return createToken(result.claims.sub, result.claims.role, undefined, {
    user_id: result.claims.user_id,
    org: result.claims.org,
  });
}
```

```typescript
import type { FileActivity } from "./types.js";

export class FileTracker {
  log(params: {
    org_id: string;
    session_id: string;
    agent_id: string;
    agent_name?: string;
    tool_name: string;
    file_path: string;
    content_hash?: string | null;
    symbols_touched?: string[] | null;
  }): void {
    const db = getDb();
    const module = this.fileToModule(params.file_path);
    db.prepare(
      `INSERT INTO file_activity
       (org_id, session_id, agent_id, agent_name, tool_name, file_path, module, content_hash, symbols_touched)
       VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)`
    ).run(
      params.org_id,
      params.session_id,
      params.agent_id,
      params.agent_name || null,
      params.tool_name,
      params.file_path,
      module,
      params.content_hash || null,
      params.symbols_touched ? JSON.stringify(params.symbols_touched) : null,
    );
  }

  getBySession(orgId: string, sessionId: string): FileActivity[] {
    const db = getDb();
    return db.prepare(
      "SELECT * FROM file_activity WHERE org_id = ? AND session_id = ? ORDER BY created_at"
    ).all(orgId, sessionId) as FileActivity[];
  }

  getHotFiles(orgId: string, sinceMinutes: number = 30): { file_path: string; agent_count: number; agents: string[] }[] {
    const db = getDb();
    const rows = db.prepare(
      `SELECT file_path, COUNT(DISTINCT agent_id) as agent_count, GROUP_CONCAT(DISTINCT agent_id) as agents
       FROM file_activity
       WHERE org_id = ?
         AND created_at > datetime('now', '-' || ? || ' minutes')
       GROUP BY file_path
       HAVING COUNT(DISTINCT agent_id) > 1
       ORDER BY agent_count DESC`
    ).all(orgId, sinceMinutes) as { file_path: string; agent_count: number; agents: string }[];
    return rows.map((r) => ({
      file_path: r.file_path,
      agent_count: r.agent_count,
      agents: r.agents.split(","),
    }));
  }

  checkFileConflict(orgId: string, filePath: string, agentId: string, withinMinutes: number = 30): { conflict: boolean; agents: string[] } {
    const db = getDb();
    const rows = db.prepare(
      `SELECT DISTINCT agent_id FROM file_activity
       WHERE org_id = ? AND file_path = ? AND agent_id != ?
         AND created_at > datetime('now', '-' || ? || ' minutes')`
    ).all(orgId, filePath, agentId, withinMinutes) as { agent_id: string }[];
    return { conflict: rows.length > 0, agents: rows.map((r) => r.agent_id) };
  }

  getFileToAgentsIndex(orgId: string, filePaths: string[], excludeAgentId: string, withinMinutes: number = 30): Map<string, Set<string>> {
    const index = new Map<string, Set<string>>();
    if (filePaths.length === 0) return index;
    const db = getDb();
    const placeholders = filePaths.map(() => "?").join(",");
    const rows = db.prepare(
      `SELECT DISTINCT file_path, agent_id FROM file_activity
       WHERE org_id = ?
         AND file_path IN (${placeholders})
         AND agent_id != ?
         AND created_at > datetime('now', '-' || ? || ' minutes')`
    ).all(orgId, ...filePaths, excludeAgentId, withinMinutes) as { file_path: string; agent_id: string }[];
    for (const r of rows) {
      let set = index.get(r.file_path);
      if (!set) { set = new Set(); index.set(r.file_path, set); }
      set.add(r.agent_id);
    }
    return index;
  }

  fileToModule(filePath: string): string {
    const normalized = filePath.replace(/^\/+/, "");
    const parts = normalized.split("/");
    if (parts.length < 2 || parts[0] === "") return "";
    return parts.slice(0, 2).join("/");
  }
}
```

```typescript
    writeHead(s: number) { statusCode = s; },

  (req as unknown as { push: (chunk: unknown) => void }).push(null);

    getRunConfig: () => null,
    setRunConfig: () => {},
  };
  await handleRest(req, res, ctx);
  return { status: statusCode, data: chunks.length ? JSON.parse(chunks.join("")) : null };
```

```typescript
  return Number.isFinite(n) && n > 0 ? n : DEFAULT_MAX_SSE_CLIENTS;
})();

const NOOP = () => {};

export class SseEmitter {
  private entries: ListenerEntry[] = [];
  private rejectedCount = 0;

  emit(type: EventType, payload: Record<string, unknown>, options: EmitOptions): void {
    const db = getDb();
    // The spread `{ ...payload, org_id: options.org_id }` deliberately OVERWRITES any
    // caller-supplied `org_id` field in `payload`. The authoritative source is
    // `options.org_id` (derived from `claims.org` in the handler), so callers cannot
    // smuggle a different org through the payload. This is intentional.
    const payloadWithOrg = { ...payload, org_id: options.org_id };
    const payloadStr = JSON.stringify(payloadWithOrg);
    const result = db
      .prepare("INSERT INTO events (org_id, type, payload) VALUES (?, ?, ?)")
      .run(options.org_id, type, payloadStr);

    const event: CoordinatorEvent = {
      id: result.lastInsertRowid as number,
      type,
      payload: payloadStr,
      created_at: new Date().toISOString(),
    };

    // Snapshot + filter by org_id, then fan-out via setImmediate.
    const snapshot = this.entries.filter((e) => e.orgId === options.org_id);
    for (const entry of snapshot) {
      setImmediate(() => {
        try { entry.listener(event); } catch { /* drop */ }
      });
    }
  }

  getEventsSince(orgId: string, lastId: number): CoordinatorEvent[] {
    const db = getDb();
    return db
      .prepare("SELECT * FROM events WHERE org_id = ? AND id > ? ORDER BY id")
      .all(orgId, lastId) as CoordinatorEvent[];
  }

  addListener(orgId: string, listener: EventListener): () => void {
    if (this.entries.length >= MAX_SSE_CLIENTS) {
      this.rejectedCount++;
      return NOOP;
    }
    const entry: ListenerEntry = { orgId, listener };
    this.entries.push(entry);
    return () => {
      this.entries = this.entries.filter((e) => e !== entry);
    };
  }

  removeAllListeners(): void { this.entries = []; }
  listenerCount(): number { return this.entries.length; }
  getRejectedCount(): number { return this.rejectedCount; }
}
```

## Task 21.5: Authenticate the `/api/events` SSE handler — with EventSource-compatible token transport

The existing SSE handler in `src/serve-http.ts` (look for `text/event-stream` or `handleSse`) registers an event listener without authentication. After Task 21, listeners require an `orgId` — without auth gating, the SSE handler has no way to derive one and would either crash or leak events across tenants.

**Design decision — browser `EventSource` does NOT support custom headers.** The standard `new EventSource('/api/events')` cannot send `Authorization: Bearer ...`. Three options:

| Option | Pros | Cons |
|---|---|---|
| Query string `?token=...` (chosen) | Works with standard EventSource | Token in URL → server logs / referrer leakage |
| Cookie-based session | Hidden from URL | Requires login endpoint to set cookie — Phase 2 work |
| Custom client (fetch + ReadableStream) | Full header support | All existing dashboards must rewrite |

**Phase 1 chooses query string** because it preserves all existing dashboards with a 1-line change (`new EventSource('/api/events?token=' + token)`). The token-in-URL leak is mitigated by: (a) short JWT TTL (15-min agent JWT after Phase 2; until then, register-flow JWTs are scoped to the session anyway), (b) TLS termination at the reverse proxy (no plaintext on the wire), (c) the existing access log convention to strip query strings on `/api/events` requests.

**Implementation**: `authenticateRequest` is extended to ALSO read `?token=...` from the URL as a fallback Bearer source. This is a minimal change to `auth.ts` and the SSE handler then just calls `authenticateRequest` like other handlers.

**Files:**
- Modify: `src/auth.ts` — `authenticateRequest` now accepts a token from `?token=` query param as fallback when no `Authorization` header is present
