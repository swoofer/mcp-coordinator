## Decision Q1 — Org membership model

**V1 decision**: 1:1 strict. `users.org_id NOT NULL`. No `user_orgs` join. No org switcher.

**Round 1 challenge** (regret + multi-tenant + contrarian + SOC 2, 5 agents):
> "Q1 is the only structural blocker. Phase 5 SaaS migration = rewrite touching JWT minting, every `getSessionClaims()` call site, every org-scoped query, and `audit_log` semantics. The schema commitment propagates everywhere. Add `user_orgs` NOW even if invariant 1:1 stays."

**V2 decision**: **1:1 invariant maintained at APPLICATION LAYER, but schema becomes N:M-ready.**

Schema changes Phase 2:
```sql
CREATE TABLE IF NOT EXISTS user_orgs (
  user_id    TEXT NOT NULL REFERENCES users(id),
  org_id     TEXT NOT NULL REFERENCES orgs(id),
  role       TEXT NOT NULL DEFAULT 'member',
  joined_at  TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, org_id)
);
CREATE INDEX idx_user_orgs_org ON user_orgs(org_id);

-- users.org_id becomes users.primary_org_id (renamed; semantics: "the one org user belongs to today")
-- (kept NOT NULL for now — invariant enforced)
ALTER TABLE users RENAME COLUMN org_id TO primary_org_id;
```

JWT claim: `active_org_id` (always `= primary_org_id` Phase 2; ready to diverge Phase 5).

App invariant: at OAuth callback, INSERT into both `users` (with `primary_org_id`) AND `user_orgs` (single row). Application code refuses to insert a 2nd `user_orgs` row for the same user in Phase 2 (will be relaxed Phase 5).

**Why this matters**: Phase 5 SaaS = drop the invariant check, expose org-switching UX. Schema unchanged. Zero migration of historical rows.

📝 Note for future: when Phase 5 lands, write a one-liner to drop the app invariant + add org-switcher endpoint. Not 6 weeks of work.

## Decision Q2 — GitHub→coord org mapping

**V1 decision**: Allowlist `COORDINATOR_GITHUB_ORG` + fallback picker C if env unset.

**Round 1 challenge** (OWASP + pentester + SOC 2 + YAGNI, 6 agents):
> "Picker fallback is a tenant-hijack vector OR worthless (picks among 0 orgs that exist). YAGNI says cut entirely. SOC 2 says fail-closed in prod."

**V2 decision**: **`COORDINATOR_GITHUB_ORG` REQUIRED. Fail-closed at boot if unset (when `COORDINATOR_OAUTH_ENABLED=true`).**

- Server refuses to start if OAuth enabled and allowlist env var unset
- Non-members get 403 + audit event `auth.login.denied.not_in_org` (with hashed identifier of the rejected GitHub user — not full PII per GDPR feedback)
- Allowlist value logged at boot (resolved string + SHA-256 hash) for audit forensics
- Allowlist env var supports single org only Phase 2 (no comma-separated list — defer to Phase 3 if needed)
- Case sensitivity: lowercase both sides before compare (GitHub login is case-preserving but case-insensitive in API)

**Picker C eliminated.** If a self-hoster has truly no GitHub org (solo dev), workaround: create a personal GitHub org `swoofer-personal` (free for individuals) and set `COORDINATOR_GITHUB_ORG=swoofer-personal`. Document this in onboarding.

**Bootstrap admin path** (B6): new env var `COORDINATOR_BOOTSTRAP_ADMIN=<github-login>`. The user matching this login at first OAuth callback gets `role='admin'` instead of `'member'`. Subsequent admin assignments via CLI verb (Phase 3).

## Decision Q6 — Multi-IdP API shape

**V1 decision**: Add `listMemberships`, `requestDeviceCode`, `pollDeviceToken` to `IdPProvider`. No abstract base. Phase 4 refactor.

**Round 1 challenge** (TS/Node + backward compat + npm community + regret, 4 agents):
> "Adding methods to a published interface breaks external implementers. Make optional. Plus: listMemberships pagination undefined, error policy undefined."

**V2 decision**: **Keep minimal extension, but with proper safeguards.**

Interface (note `?:` on new methods for backward compat):
```ts
interface IdPProvider {
  name: string;
  buildAuthUrl(state, redirectUri, codeChallenge?): string;
  exchangeCode(code, redirectUri, codeVerifier?): Promise<IdpUserInfo>;
  
  // NEW (optional for backward compat with hypothetical Phase 1 external impls)
  listMemberships?(accessToken: string): Promise<string[]>;
  requestDeviceCode?(): Promise<DeviceCodeResponse>;
  pollDeviceToken?(deviceCode: string): Promise<DevicePollResult>;
}
```

`listMemberships` semantics (spec-mandated):
- MUST fetch all pages from GitHub `/user/orgs` (no cap — typical user has <50 orgs)
- MUST be called fresh on every OAuth callback AND every refresh rotation (no caching; otherwise removed members keep access 30 days)
- Required GitHub OAuth scope: `read:org`
- On 401 from IdP (token revoked at IdP): throws `IdPTokenRevoked` → coordinator force-logout user
- On 5xx / timeout (5s): throws `IdPTransientError` → coordinator retries 1x, then 503 to user

`DeviceCodeResponse` / `DevicePollResult` shapes pinned in spec (RFC 8628 compliant).

📝 Note for future: `BaseOAuthProvider` extract when 2+ concrete providers ship (Phase 4 Google/OIDC). Non-goal Phase 2.

## Decision Q4 — PKCE state storage

**V1 decision**: SQLite `oauth_state` table, 10min TTL, `consumed_at` one-time use, sweeper.

**Round 1 challenge** (OWASP + pentester + DB + distributed + OAuth RFC, 5 agents):
> "CAS race on consumed_at. State must bind to user-agent. Sweeper race with callback handler. Schema needs `idp` column for mix-up attack mitigation."

**V2 decision**: **Same approach, hardened.**

Schema (final):
```sql
CREATE TABLE IF NOT EXISTS oauth_state (
  state                TEXT PRIMARY KEY,
  code_verifier        TEXT NOT NULL,
  redirect_uri         TEXT NOT NULL,
  provider             TEXT NOT NULL,                    -- 'github' Phase 2; required for mix-up attack defense
  user_agent_hash      TEXT,                             -- SHA-256(User-Agent header); bind state to browser
  created_at           INTEGER NOT NULL,
  expires_at           INTEGER NOT NULL,                 -- created_at + 10min absolute (not sliding)
  consumed_at          INTEGER
);
CREATE INDEX idx_oauth_state_expires ON oauth_state(expires_at);
```

Consumption (atomic CAS, mandatory SQL):
```sql
UPDATE oauth_state
SET consumed_at = :now
WHERE state = :state AND consumed_at IS NULL AND expires_at > :now
RETURNING code_verifier, redirect_uri, provider, user_agent_hash;
```
Check `rowsAffected == 1`. If 0 → state replay or expired → 400 + audit `auth.state.replay`.

User-agent binding: at callback, recompute `SHA-256(req.headers['user-agent'])`, compare to stored. Mismatch → 400 + audit. (RFC 9700 §4.7 binding requirement.)

Sweeper specs (B/C agents converged):
- Cadence: 60 seconds (setInterval in main loop)
- Batch size: `DELETE ... WHERE expires_at < :now - 60 LIMIT 1000` (60s buffer to avoid race with in-flight callback)
- Shutdown: drain on SIGTERM
- Error policy: log + continue (don't crash); circuit-break if 5 consecutive failures

Entropy: `state = crypto.randomBytes(32).toString('base64url')` (256 bits). `code_verifier = crypto.randomBytes(32).toString('base64url')` (64 chars, RFC 7636 compliant). PKCE method pinned to `S256`; `plain` rejected at parse.

## Decision Q5 — Device Flow approval UX

**V1 decision**: HTML inline at coordinator. Session cookie post-OAuth. Anti-scope-creep rule.

**Round 1 challenge** (OWASP + pentester + TS + crypto + regret, 7 agents):
> "XSS in template literals (escapeHtml mandatory). CSRF with SameSite=Lax allows cross-site POST (need Strict or token). Cookie attributes need __Host- prefix. Regret confirms 'anti-scope rule lasted 8 months.'"

**V2 decision**: **Same approach, security-hardened + seam for future refactor.**

HTML rendering:
- ALL interpolation MUST use `escapeHtml(s)` helper (5 replacements: `& < > " '`)
- Lint convention: raw `${}` in HTML templates forbidden; PR check enforces
- Single `render(template, context)` seam — anti-scope rule says "no new HTML routes," but the seam exists so Phase 5 SPA migration = swap one function
- CSP header on auth pages: `default-src 'none'; script-src 'none'; style-src 'self' 'unsafe-inline'; form-action 'self'`
- Cache-Control: `no-store` on all `/auth/*` pages (prevents code/state in browser history)

Session cookie (final attributes):
- Name: `__Host-coordinator_session` (`__Host-` prefix enforces secure + path=/ + no Domain)
- HttpOnly: true
- Secure: true (false only when `NODE_ENV=development` AND `COORDINATOR_PUBLIC_URL` is `http://localhost*`)
- SameSite: **Strict** (not Lax — closes CSRF on top-level POST)
- Path: `/`
- Max-Age: `JWT access TTL` (re-issued on each refresh)

CSRF protection on `POST /auth/device/approve`:
- Double-submit token: random 32 bytes, set in `__Host-coordinator_csrf` cookie (HttpOnly=false so JS can read) AND required as form hidden field `_csrf`
- Constant-time comparison
- Token bound to session cookie value (HMAC over session JWT jti)

Cookie scenario in `authenticateRequest`:
- Scenario 5: read `__Host-coordinator_session`, validate JWT, populate claims
- Bearer header MUST take precedence over cookie (CLI flows always Bearer)

`oauth_state` → cookie binding: spec must define how the callback handler reconciles the browser-side state cookie (containing state hash) with the server-side `oauth_state` row. Concrete pseudo-code in spec.

📝 Note for future: when Phase 5 SPA dashboard arrives, the 4 HTML routes here become candidates for migration. The `render()` seam makes this a 1-day refactor.

## Decision Q7 — Refresh token storage

**V1 decision**: Pattern B (JWT refresh + jti in DB). No token_hash.

**Round 1 challenge** (9 agents):
> "Chain revoke is theater without family_id + parent_jti. Concurrent refresh = legitimate users logged out. HS256 should plan RS256 path. Reuse detection grace window needed."

**V2 decision**: **Pattern B confirmed, but with proper rotation semantics.**

Schema additions:
```sql
ALTER TABLE refresh_tokens ADD COLUMN family_id     TEXT;
ALTER TABLE refresh_tokens ADD COLUMN parent_jti    TEXT;
ALTER TABLE refresh_tokens ADD COLUMN revoked_reason TEXT;  -- enum: rotated|reuse_detected|logout|logout_all|admin|key_rotation
CREATE INDEX idx_refresh_family ON refresh_tokens(family_id, revoked_at);
```

`family_id` semantics: new UUID at original login; copied to every rotation descendant. On rotation, new row inherits parent's `family_id`, stores `parent_jti = parent.jti`.

Reuse detection algorithm (mandatory spec text):
```
on /api/auth/refresh(token):
  claims = jwtVerify(token)
  row = SELECT * FROM refresh_tokens WHERE jti = claims.jti
  
  if row.revoked_at IS NOT NULL:
    # Reuse detected!
    if row.revoked_reason == 'rotated' AND (now - row.revoked_at) < 10s:
      # Legitimate concurrent retry — return the successor token
      successor = SELECT * FROM refresh_tokens WHERE parent_jti = row.jti
      return mint cached successor
    else:
      # Actual replay attack — revoke entire family
      UPDATE refresh_tokens 
      SET revoked_at = now, revoked_reason = 'reuse_detected'
      WHERE family_id = row.family_id AND revoked_at IS NULL
      auditLog('auth.refresh.chain_revoked', ...)
      return 401 with WWW-Authenticate
  
  # Normal rotation
  newJti = randomUUID()
  BEGIN TRANSACTION
    UPDATE refresh_tokens SET revoked_at = now, revoked_reason = 'rotated' WHERE jti = claims.jti
    INSERT INTO refresh_tokens (jti = newJti, family_id = row.family_id, parent_jti = row.jti, ...)
  COMMIT
  return new access + refresh JWT pair
```

Backward compat: Phase 1 `refresh_tokens` rows (if any) get backfilled `family_id = uuid()`, `parent_jti = NULL` at migration.

📝 Future evolution to capture in spec:
- **HS256 → RS256/EdDSA**: Phase 2 ships with `kid` header in JWT (single key today, but kid lets us rotate or add asymmetric later without breaking change). Plan asymmetric migration when 2nd verifier emerges (Phase 4 federation, Phase 5 SaaS).
- **JWT payload minimization**: Phase 2 JWT claims = `{sub, jti, iat, exp, iss, family_id, active_org_id}`. NO `email`, NO `github_login`, NO `name` (lookup server-side via /api/auth/me). Reduces PII exposure if cookie/JWT leaks.

## Decision Q8 — Logout semantics

**V1 decision**: `/logout` (local) + `/logout-all` (global). Audit events. No UI.

**Round 1 challenge** (4 agents):
> "Add `token_epoch` bump for logout-all OR document the 15min access lag explicitly. RFC 7009 compliance: rename to `/revoke`. logout-all needs `except_current` option."

**V2 decision**: **Same endpoints, RFC-aligned, with token_epoch addition.**

Endpoints:
- `POST /api/auth/logout` (RFC 7009 alias: `/api/auth/revoke`)
  - Revokes current refresh jti (extracted from Bearer or cookie)
  - Sets `revoked_reason = 'logout'`
  - Idempotent (already-revoked → 200/204)
  - Clears `__Host-coordinator_session` cookie if cookie auth path
  
- `POST /api/auth/logout-all`
  - Revokes ALL `revoked_at IS NULL` rows for `user_id`
  - Accepts optional `{ except_current: true }` to keep the calling jti alive (prevents self-logout footgun)
  - Bumps `users.token_epoch` (new column): JWT validation rejects tokens with `iat < user.token_epoch`
  - Sets `revoked_reason = 'logout_all'`

Schema addition:
```sql
ALTER TABLE users ADD COLUMN token_epoch INTEGER NOT NULL DEFAULT 0;
```

Token validation (modified):
```
verify JWT signature
check claims.iat >= user.token_epoch  // <-- new check
check claims.exp > now
```

This closes the 15min access-JWT-survives-logout-all window concern from HIPAA/SOC 2/ops reviewers.

Audit events: `auth.logout.local`, `auth.logout.global` (with `revoked_count`).

## Decision Q3 — JWT TTLs

**V1 decision**: 15min access + 30d refresh, env-configurable via `COORDINATOR_JWT_ACCESS_TTL` + `COORDINATOR_JWT_REFRESH_TTL`.

**Round 1 challenge** (HIPAA + SOC 2 + contrarian, 3 agents):
> "15min access ≠ idle timeout (refresh transparent). 30d = stolen token = 30d access. Need bounds on env vars. Need idle timeout for regulated. Contrarian: 1h more honest."

**V2 decision**: **Keep defaults, add bounds, add idle timeout, document.**

Configuration:
- `COORDINATOR_JWT_ACCESS_TTL` (default `"15m"`, max `"60m"` — enforced at boot)
- `COORDINATOR_JWT_REFRESH_TTL` (default `"30d"`, max `"90d"` — enforced at boot)
- `COORDINATOR_SESSION_IDLE_TIMEOUT` (default `null` = disabled, optional `"15m"` for regulated deployments)
- Boot logs effective values (so ops + SOC 2 audit can verify)

Idle timeout (when configured):
- `refresh_tokens.last_used_at` updated on every refresh
- Refresh request after `now - last_used_at > idle_timeout` → 401 + force re-auth
- Audit event: `auth.refresh.idle_expired`

JWT validation:
- Algorithm pinned to `HS256` (Phase 2) — reject `alg: none`, `alg: RS256` mismatch
- Clock skew leeway: ±30 seconds on `iat`, `exp`, `nbf`
- `kid` header included even with single key (Phase 4 asymmetric upgrade)

Backward compat: if `COORDINATOR_JWT_ACCESS_TTL` unset, falls back to Phase 1 `defaultExpiry` value if set, else `"15m"`. Loud warning if Phase 1 value > 60m.

📝 Document in spec: "15min access ≠ session termination. Refresh transparently re-issues. For regulated deployments, set `SESSION_IDLE_TIMEOUT`. For incident response, `/logout-all` + `token_epoch` is the immediate-effect mechanism."
